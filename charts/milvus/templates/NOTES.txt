Inspect the deployment:

  # Milvus custom resource status
  kubectl get milvus {{ include "milvus-cluster.milvusName" . }} -n {{ .Release.Namespace }}
  kubectl describe milvus {{ include "milvus-cluster.milvusName" . }} -n {{ .Release.Namespace }}

  # Pods and services the Operator created
  kubectl get pods -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ include "milvus-cluster.milvusName" . }}
  kubectl get svc  -n {{ .Release.Namespace }} -l app.kubernetes.io/instance={{ include "milvus-cluster.milvusName" . }}

  # Recent events (Operator reconciliation, scheduling, pulls)
  kubectl get events -n {{ .Release.Namespace }} --sort-by=.lastTimestamp

Reach the Proxy from your workstation (Proxy is ClusterIP by default):

  kubectl port-forward -n {{ .Release.Namespace }} svc/{{ include "milvus-cluster.milvusName" . }}-milvus 19530:19530

Reminders:
  * All external dependencies (Kafka, etcd, Ozone S3 Gateway) must already exist.
  * Credentials are stored in Kubernetes Secrets and injected into Milvus pods as
    environment variables / mounted files — they are never printed here.
  * Chart-created Secrets (if enabled) are stored in Helm release metadata; use an
    external secret manager for production GitOps.
  * Test your backup AND restore procedure before relying on this cluster.
